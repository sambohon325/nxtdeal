# Contributing to NXTDeal

Thanks for considering a contribution. The project is entering community stewardship and does not have a guaranteed maintainer response time.

## Before opening a pull request

- Search existing issues and focused branches to avoid duplicating work.
- Keep changes narrow and explain the user problem they solve.
- Do not include real customer, employee, dealer, credential, or production data.
- Never commit secrets, local environment files, generated runtime stores, or unlicensed media.
- Preserve current API and data contracts unless the change explicitly migrates them.
- Include focused regression tests for behavior changes. Report exactly which checks you ran and what failed.
- For tenant isolation, authentication, permissions, finance, compliance, AI actions, or external delivery, describe the security and rollback implications and request an independent review.

## Pull request description

Include the problem, approach, affected modules, test/build evidence, known limitations, any migration/configuration steps, and rollback plan. Label synthetic/demo results as such. A passing unit test does not establish production readiness.

## Conduct

Be respectful and specific. Critique code and decisions without targeting people. Harassment, threats, doxxing, and sharing private data are not acceptable. A maintainer may close contributions that violate these expectations.
